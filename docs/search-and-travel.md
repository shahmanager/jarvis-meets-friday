# Google Search grounding and travel-price scope

`src/search.ts` provides `geminiSearch(apiKey, model, query)` using Gemini's `generateContent` REST API with `tools: [{ google_search: {} }]`. Google documents this shape for current grounded models and documents the grounding response's answer, search queries, source chunks, citation supports, and Search Suggestions. The model ID stays an explicit argument; Google's current guide uses `gemini-3.8-flash` and lists it as Search-grounding capable. Check Google's model guide before configuring a model because support changes.

The adapter returns the exact answer text, safe HTTPS source links with their original chunk indices, inline-support ranges, search queries, and the `searchEntryPoint.renderedContent` as an opaque `searchEntryPointHtml` string. That field is untrusted provider HTML: never insert it with `innerHTML` into the application DOM or treat it as an instruction. The app serves it through a separate authenticated sandbox document without scripts or same-origin privileges. The consuming UI must present grounded answers with their associated Google Search Suggestions as required by Google's terms; this adapter alone does not implement that UI. If no grounding metadata arrives, `grounded` is false and no citations are claimed.

The adapter is wired as `web_search` for both roles, using the encrypted Gemini key in Settings. Work shows the complete grounded response, citations and isolated Search Suggestions; routine polling omits these large payloads. Integration should use the Gemini key/model already owned by Settings, keep the key in the `x-goog-api-key` header, and expose this function as a read-only search tool. The caller must require exact disclosure approval before sending private or sensitive query text to Google. Gemini API requests can be processed/stored under Google's service terms; for Search grounding, Google says prompts, context, and output are retained for 30 days to produce results and improve/debug the grounding service. Review the current terms and use paid Gemini API quota for sensitive professional data only after the owner's policy decision.

This covers current public-web research, not exact flight quotes or booking. Search snippets and model-generated itineraries can be stale and do not prove a seat or fare is available. A real fare quote needs a separately configured airline, GDS, or travel-retailer offers API that returns current inventory and total pricing for the requested dates, passenger count, cabin, bags, currency, and tax/fee breakdown; reprice the chosen offer immediately before purchase. Any displayed quote needs its source, currency, retrieval time, and availability/reprice caveat. No such travel API is configured or live-tested here. The user's trip-planning example does not add a dedicated travel integration.
