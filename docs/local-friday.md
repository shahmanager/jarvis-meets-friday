# Friday's local document index

The laptop companion can build a private search index for one folder chosen by the owner. The index, extracted text, source names, hashes, and timestamps stay in the companion's local state directory. The companion polls the existing paired-device channel; it does not open an inbound listener, create a VM, or run a local language model.

Choose a folder in the companion and refresh the index. Each `search`, `read`, or `aggregate` request first refreshes a bounded scan, then prepares a result for the existing release review. Search returns up to 12 excerpts of at most 700 characters. Read returns up to 12 indexed paragraphs for one selected path, with the result bounded to 8,000 characters. Aggregate returns source and paragraph counts without document text. Results include the relative source path, SHA-256 content hash, modification time, file size, parser, index time, and paragraph or PDF page location. Results mark when a scan hit a configured cap; a zero-result search does not prove that information is absent.

The scan covers at most 500 files, 50 MB of source data, and 20 MB of indexed text per refresh. Plain text files supported by the existing policy are limited to 256 KB each. DOCX files are limited to 5 MB compressed, 10 MB expanded, 500 archive entries, and 2 MB of extracted text; text is read from `word/document.xml` using Python's standard library. DOCX/PDF parsing runs in a child process with a 20-second timeout and, where Python exposes `resource`, CPU and 512 MB address-space limits. On Windows the child process has a timeout, but Python provides no equivalent address-space limit. PDF files are limited to 5 MB and 100 pages, with at most 2 MB of extracted text. PDF extraction needs the optional `pypdf` package (`python -m pip install pypdf`); it is not installed by the companion. Encrypted PDFs are skipped. OCR, embedded images, legacy DOC files, and other formats are not supported.

Hidden paths, symlinks, and paths that resolve outside the chosen folder are excluded. A refresh removes deleted, changed, unreadable, or out-of-budget entries from the index before a result can be prepared. Changing folders clears the previous folder's index. **Clear local index** removes the stored text and metadata and pauses indexing; it does not delete source files. Choose **Refresh local index** to resume.

Document names and metadata can themselves be sensitive. The indexed corpus remains on the device until cleared. The default release flow asks the owner to edit or decline every prepared result. An optional task-scoped grant can allow subsequent prepared search/read/aggregate results to auto-release for 10 minutes, but only for the same task, provider/model/role snapshot, selected-folder root, and unchanged indexed source hashes. The owner must enable the companion checkbox and confirm the initial release; the grant lives only in memory and clears when the app closes, the folder or task changes, the recipient changes, or source versions change. Each request refreshes the local index before preparing a result. Every result stays bounded to 12,000 characters. Asking the small-model API is a separate disclosure and requires its own confirmation. Regex masking is not a privacy guarantee. There is no automatic cloud corpus, private local inference, or local knowledge graph.

On Unix, the companion state directory is restricted to mode `0700`, and the local SQLite databases to `0600`. Windows uses the user's local application-data directory and protects the paired credential with DPAPI.
